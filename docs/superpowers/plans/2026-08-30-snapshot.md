# Snapshot 实现计划

> **面向 AI 代理的工作者：** 使用 `executing-plans` 逐任务实现此计划。

**目标：** 持久化按交易对、按序列版本化的内存订单簿快照。

**架构：** 领域模型与 JSON 原子文件读写分离；读取端按序列从新到旧回退有效快照。

**技术栈：** Java 17、Jackson、JUnit 5、AssertJ。

### 任务 1：快照领域模型

**文件：** 创建 `domain/snapshot/MatchingSnapshot.java`、`SnapshotOrder.java`；测试 `MatchingSnapshotTest.java`。

- [ ] 先写构造非法序列、订单方向与空列表的失败测试。
- [ ] 运行 `mvn -pl cex-matching-engine -am -Dtest=MatchingSnapshotTest test`，确认缺少类型而失败。
- [ ] 实现不可变模型、正序列校验和买卖订单方向校验，全部公开方法写中文 Javadoc。
- [ ] 重跑定向测试并提交 `feat: 新增订单簿快照模型`。

### 任务 2：原子快照读写器

**文件：** 创建 `infrastructure/snapshot/SnapshotCodec.java`、`SnapshotWriter.java`、`SnapshotReader.java`、异常类型；测试对应 Writer/Reader。

- [ ] 先写 JSON 往返、`.tmp` 刷盘后原子替换、损坏最新文件回退的失败测试。
- [ ] 实现固定字段 JSON、同目录临时文件、`force(true)`、`ATOMIC_MOVE` 和降序有效文件查找。
- [ ] 运行快照定向测试并提交 `feat: 新增原子订单簿快照读写`。

### 任务 3：快照管理器与模块回归

**文件：** 创建 `infrastructure/snapshot/SnapshotManager.java`；测试 `SnapshotManagerTest.java`。

- [ ] 先写按交易对隔离、非法交易对路径拒绝和空订单簿快照测试。
- [ ] 复用 WAL 同等级的路径校验语义实现管理器。
- [ ] 运行 `mvn -pl cex-matching-engine -am test`，审查并提交 `feat: 新增按交易对管理的订单簿快照`。

## 四、数据库设计(`docker/mysql/init/02-order-tables.sql`)

### orders

```sql
CREATE TABLE orders (
    id               BIGINT       NOT NULL PRIMARY KEY,        -- 自研 Snowflake 主键
    order_id         BIGINT       NOT NULL,
    user_id          BIGINT       NOT NULL,
    client_order_id  VARCHAR(64),
    symbol           VARCHAR(32)  NOT NULL,
    side             VARCHAR(10)  NOT NULL,
    type             VARCHAR(20)  NOT NULL,
    price            DECIMAL(32,16),
    quantity         DECIMAL(32,16) NOT NULL,
    filled_quantity  DECIMAL(32,16) NOT NULL DEFAULT 0,
    filled_amount    DECIMAL(32,16) NOT NULL DEFAULT 0,
    quote_amount     DECIMAL(32,16),                            -- 市价买单的冻结金额
    status           VARCHAR(32)  NOT NULL,
    time_in_force    VARCHAR(10),
    version          BIGINT       NOT NULL DEFAULT 0,           -- 乐观锁(MyBatis-Plus 插件已就绪)
    created_at       DATETIME     NOT NULL,
    updated_at       DATETIME     NOT NULL,
    UNIQUE KEY uk_order_id(order_id),
    UNIQUE KEY uk_user_client_order(user_id, client_order_id),
    INDEX idx_user_symbol_time(user_id, symbol, created_at),
    INDEX idx_user_status_time(user_id, status, created_at)
);
```

### order_event_outbox

```sql
CREATE TABLE order_event_outbox (
    id             BIGINT       NOT NULL PRIMARY KEY,
    event_id       VARCHAR(64)  NOT NULL,

    payload        TEXT         NOT NULL,

    retry_count    INT          NOT NULL DEFAULT 0,
    next_retry_time DATETIME    NOT NULL,

```

### processed_event(消费幂等)

```sql
CREATE TABLE processed_event (

    processed_at DATETIME    NOT NULL,

```

### symbol_config(预置 BTC_USDT / ETH_USDT)

```sql
CREATE TABLE symbol_config (
    id             BIGINT       NOT NULL PRIMARY KEY,
    symbol         VARCHAR(32)  NOT NULL,
    base_currency  VARCHAR(16)  NOT NULL,
    quote_currency VARCHAR(16)  NOT NULL,
    price_scale    INT          NOT NULL,
    quantity_scale INT          NOT NULL,
    min_quantity   DECIMAL(32,16) NOT NULL,
    min_amount     DECIMAL(32,16) NOT NULL,

    updated_at     DATETIME     NOT NULL,

```

## 五、领域模型与状态机

`Order` 聚合根:字段 orderId/userId/clientOrderId/symbol/side/type/price/quantity/quoteAmount/filledQuantity/filledAmount/status/timeInForce/createdAt/updatedAt/version。

方法:`markPendingMatch() / markPartiallyFilled() / markFilled() / cancel() / reject()`,内部校验合法流转,非法抛 OrderStatusInvalidException(FILLED 不能再 cancel)。

```
NEW → PENDING_MATCH → PARTIALLY_FILLED → FILLED
NEW → REJECTED
NEW/PENDING_MATCH/PARTIALLY_FILLED → CANCELED
```

## 六、创建订单(事务边界)

流程:

1. 幂等预查(clientOrderId)→ 命中返回首次结果
2. 参数校验(side/type/TIF 枚举、price/quantity 正数)
3. 交易对校验:SymbolConfigService(Redis → DB),校验 status=ACTIVE
4. 精度校验:按 price_scale / quantity_scale
5. 最小金额校验:price × quantity >= min_amount
6. 生成 orderId(自研 Snowflake)
7. 冻结金额计算(FreezeCalculator):
   - 限价买单:price × quantity
   - 限价卖单:quantity
   - 市价买单:quoteAmount(请求传入)
   - 市价卖单:quantity
8. 【事务外】AccountServiceClient.freeze(userId, currency, amount, bizType=FREEZE_ORDER, bizId=orderId)——本期 Mock;冻结接口幂等(bizType+bizId 唯一)
9. 【@Transactional】INSERT orders(初始状态 = PENDING_MATCH,表示已提交待撮合,与创建接口返回一致) + INSERT order_event_outbox(ORDER_CREATED, payload=OrderEvent JSON)
10. 事务提交后由 OutboxRelay 定时发送 Kafka
11. 补偿:步骤 9 事务失败 → catch 中调用 AccountServiceClient.unfreeze 解冻

关键点:Kafka 发送绝不在数据库事务内;冻结 RPC 在事务外调用,失败不写订单;本地事务失败必须解冻(资金不会永久冻结)。

## 七、取消订单

1. 查询订单 + 归属校验(userId)
2. 状态机校验:仅 NEW/PENDING_MATCH/PARTIALLY_FILLED 可取消
3. 【@Transactional】UPDATE orders SET status=CANCELED + INSERT order_event_outbox(ORDER_CANCELED, action=CANCEL)
4. 事务提交后 relay 发送 Kafka
5. 【事务外】unfreeze 解冻剩余冻结资产:买单解冻额 = price × (quantity - filledQuantity),卖单解冻额 = quantity - filledQuantity(即未成交部分的冻结金额)

## 八、Kafka 消息设计

- Topic:`cex.order.event`(TopicConstants.TOPIC_ORDER_EVENT),key=symbol(同交易对同分区保序)
- Producer:`acks=all` + `enable.idempotence=true`(补到 application.yml)
- 事件模型:扩展共享 OrderEvent,新增 clientOrderId 字段(向后兼容)
- 消费:`OrderEventConsumer` 监听 cex.trade.event(group=cex-order),按 buyOrderId/sellOrderId 更新 filledQuantity/filledAmount + 状态机流转;processed_event 按 (tradeId, consumer) 幂等,重复消息直接忽略
- Outbox Relay:@Scheduled 1s 轮询 INIT/SENDING 且 retry_count < 10;失败指数退避(next_retry_time = now + 2^retry_count 秒);超限置 FAILED + 告警日志

## 九、接口设计

| 接口 | 方法 | 说明 |
|---|---|---|
| POST /api/v1/orders | 创建订单 | 重复 clientOrderId 返回首次结果 |
| DELETE /api/v1/orders/{orderId} | 取消订单 | 支持 clientOrderId 参数 |
| GET /api/v1/orders/{orderId} | 查询订单 | 归属校验 |
| GET /api/v1/open-orders | 当前委托 | symbol 参数,状态 IN (NEW, PENDING_MATCH, PARTIALLY_FILLED) |
| GET /api/v1/orders | 历史订单 | 游标分页 |

游标分页:WHERE (created_at < ? OR (created_at = ? AND order_id < ?)),ORDER BY created_at DESC, order_id DESC LIMIT 20。统一 ApiResult 包装 + ErrorCode 枚举。
